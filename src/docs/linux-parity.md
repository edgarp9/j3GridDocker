# Windows/Linux 기능 동등성 점검

기준 동작은 기존 Win32 구현이다. Linux UI는 GTK4 entry이며, 외부 창 제어는 X11 세션에서만 지원한다. Wayland에서는 외부 창 제어가 OS 보안 정책상 불가능하므로 해당 기능은 지원 불가 상태로 보고한다.

| 기능 | Windows Win32 | Linux GTK4/X11 | 상태 |
| --- | --- | --- | --- |
| 단일 코드베이스 빌드 | Win32 entry | GTK4 entry | 구현 |
| 빌드/테스트 환경 | Windows GNU/MSVC target check 가능 | Linux native build/test/clippy 가능 | 구현 |
| 메인 메뉴 | Workspace/Layout/Presets/View/Options/Window/Help | 동일 메뉴 그룹, Win32 라벨/활성 조건 반영 | 구현 |
| 탭 생성/전환/닫기 | 지원 | 지원 | 구현 |
| 탭 이름 변경 | modal edit dialog | GTK dialog | 구현 |
| 다른 탭 닫기 | context target 기준 best-effort 삭제 | context target 기준 best-effort 삭제 | 구현 |
| 탭 drag reorder/window move | visible tab reorder + 숨김 상태 tab body main window move | GTK drag insertion separator + edge scroll, 숨김 상태 tab body main window move | 구현 |
| 탭 overflow | hidden tab dropdown | first-visible 기반 hidden tab dropdown, full-tab capacity 기준 | 구현 |
| 탭 tooltip | docked window title 목록, 빈 제목 placeholder | X11 window title 목록, 빈 제목 placeholder | 구현 |
| 탭바 빈 공간 메뉴/더블클릭 | context menu + preset/window 항목 + maximize/restore toggle | GTK context menu + preset/window 항목 + maximize/restore toggle | 구현 |
| 영역 선택 | region click/context | region click/context | 구현 |
| 영역 분할/삭제 | command/menu/context | command/menu/context | 구현 |

| window owner/z-order 보정 | Win32 owner/z-order 사용 | X11 ConfigureWindow raise 요청 + dock 중 `_NET_WM_STATE_ABOVE` | X11 구현, WM 정책 영향 |
| tab preset 저장 | layout + executable path + arguments 편집 | layout + X11 `_NET_WM_PID` 기반 executable path + arguments 편집 | X11 구현 |
| tab preset 불러오기 | layout 적용 + process launch/window 재탐색 dock | X11 preflight 후 layout 적용 + process launch/X11 pid window scan dock | X11 구현 |
| tab preset 편집/삭제 | 지원 | GTK dialog 지원 | 구현 |
| UI 옵션 저장 | 설정 파일, startup session 보존 정책 | 같은 설정 파일 모델과 startup session 보존 정책 | 구현 |
| 종료 undock | 설정 저장 후 모든 placement restore, 실패 시 close 중단 | 설정 저장 후 X11 restore, 실패 시 close 중단 | X11 구현 |

2026-06-16~2026-06-17 점검에서 수정한 차이:

- Linux 최상위 Workspace/Layout/Window 메뉴 라벨과 active tab이 없을 때의 민감도를 Win32 기준으로 맞췄다.
- Windows entry가 runtime에서 사용하는 splitter drag/cache helper가 `#[cfg(test)]`로 가려져 Windows target check가 실패하던 문제를 보정했다.
- Linux Options 메뉴를 checked 항목 중심으로 바꾸고, Show/Hide 버튼 우클릭에서도 같은 옵션 메뉴를 열 수 있게 했다.
- 작업 영역 UI 숨김 상태에서 menu/status/drawing area/title decoration을 숨기고, 숨김 전환 후 active tab external window bounds를 다시 동기화한다.
- 탭 context menu에는 tab preset Save/Load 항목을, 빈 탭바 context menu에는 tab preset Save/Load/Edit/Delete 항목을 추가했다.
- inactive tab context의 Close other tabs가 먼저 tab 전환을 하지 않고 Win32처럼 context target tab 기준으로 동작한다.
- Linux 영역 context menu의 Undock 항목 라벨을 Win32 context menu 라벨과 맞췄다.
- Linux Presets 메뉴와 tab preset context 항목을 choice dialog 대신 preset 이름 하위 popover leaf로 실행하게 바꿔 Win32 메뉴 선택 흐름에 맞췄다.
- Linux Options 주 메뉴의 Language 항목을 Win32처럼 하위 메뉴 구조로 맞췄고, tab overflow 항목 라벨도 Win32처럼 `번호 + 탭 이름` 형식으로 맞췄다.
- Linux About dialog 설명 문구를 현재 Win32 기준 문구와 맞췄다.
- Linux preset 저장은 `Tab Preset N` 기본 이름으로 바로 preset 편집 dialog를 열고, 프로그램 arguments parser는 Win32처럼 빈 argument와 닫히지 않은 quote를 처리한다.
- Wayland/비-X11 GTK surface에서는 external window drop과 preset load를 layout 변경/프로그램 실행 전에 거부한다.
- Linux 메뉴 구성 중 `refresh_all`/context menu 콜백이 이미 `RefCell` borrow를 잡고 있는 상태에서 language/preset 목록을 다시 borrow하던 panic을 제거했다.
- Linux 메뉴 action은 GTK popover signal 안에서 즉시 상태를 바꾸지 않고, Win32 `TrackPopupMenu` 이후 command 처리처럼 popover를 닫은 뒤 idle에서 실행하도록 바꿨다.
- Linux preset edit/rename dialog response에서 `borrow_mut()` 임시값이 match arm까지 살아 재진입 panic을 일으키던 경로를 지역 변수로 분리했다.
- Linux 메인/메뉴/탭/dialog CSS를 Win32 고정 밝은 팔레트 기준으로 보정했고, active region 색상도 Win32 COLORREF 표시 결과와 맞췄다.
- Linux 언어 변경 시 상단 `New` 버튼 라벨도 `새 탭`으로 갱신되도록 보정했다.
- Linux Window 메뉴의 Close가 window close request 안에서 다시 `borrow_mut()` 하며 panic 나던 경로를 window clone 후 close 호출로 수정했다.
- Linux Window 메뉴의 Maximize 실행 직후 메뉴 label이 `Maximize window`로 남던 문제를 Win32처럼 상태 캐시 기반 `Restore window` label로 갱신되게 수정했다.
- Linux app/domain/window/settings 오류 status가 UI 언어와 다르게 한국어 원문으로 표시되던 경로를 현재 UI 언어 기준 메시지로 보정했다.
- Linux Workspace/Layout/Presets/drop/preset restore 성공 status가 English 고정으로 표시되던 경로를 현재 UI 언어 기준 메시지로 보정했다.
- Linux 종료 시 메뉴 popover가 붙은 `GtkButton` finalize 경고를 내던 경로를 종료 직전 popover detach로 정리했다.
- Linux 시작 시 `present()` 도중 `realize` 콜백이 같은 `RefCell`을 다시 빌려 panic 나던 경로를 window clone 후 present하도록 고쳤다.
- Linux Window Minimize를 Win32 `WM_SIZE/SIZE_MINIMIZED` 흐름처럼 active tab 외부창 hide, drop/drag 상태 초기화, restore 시 active tab show/sync로 맞췄다.
- Linux 격리 X11/KWin 검증에서 `Alt+F4`가 window manager close로 전달되지 않는 경우를 재현했다. Win32가 `DefWindowProcW` 기본 처리로 제공하는 창 닫기 단축키와 맞추기 위해 Linux GTK entry가 `Alt+F4`를 직접 받아 `Window > Close Window`와 같은 close request 흐름을 실행하도록 보정했다.
- Linux shutdown이 main window minimized 상태에서는 Win32처럼 active tab이 이미 hidden인 것으로 보고 restore/undock하도록 맞췄다.
- Linux X11 drop target이 KWin 같은 reparenting WM의 frame window로 잡혀 dock 상태만 바뀌고 실제 client 창 위치/크기가 바뀌지 않던 문제를, `WM_STATE`가 있는 descendant client XID로 정규화해 수정했다.
- Linux 작업 영역 UI 숨김 상태에서 tab body drag가 Win32처럼 main window move로 전환되도록, GTK drag offset을 X11 main window `ConfigureWindow` 위치 변경으로 적용했다.
- Linux 작업 영역 UI 숨김 상태에서 Ctrl을 누르면 Win32처럼 top-level splitter overlay가 표시되고, 외부 창 위에서도 splitter drag 입력을 받을 수 있게 X11 override-redirect overlay window를 추가했다.
- Linux X11 snapshot/restore가 Win32 `WindowDisplayState`처럼 minimized/maximized 상태를 구분하도록 `WM_STATE` IconicState와 `_NET_WM_STATE_MAXIMIZED_HORZ/VERT` 판정 및 복원 요청을 추가했다.
- Linux X11 snapshot에 Win32 snapshot identity guard와 같은 custom X11 property token을 심어, XID가 재사용된 새 창을 기존 placement로 오인하지 않도록 보강했다.
- Linux docked X11 창이 메뉴/다이얼로그 조작 뒤 main window 뒤로 내려가던 문제를, dock 중 `_NET_WM_STATE_ABOVE` 적용과 popover/dialog 종료 후 active tab sync로 보정했다. Undock/Close restore 때는 snapshot의 원래 ABOVE 상태로 되돌린다.
- Linux active tab에 배치된 외부 창이 OS active window로 관측되면 해당 region을 active region으로 선택하게 해 Win32 `WM_ACTIVATE` 기반 active region 동기화에 맞췄다.
- 검증 환경에서 `cargo clippy --all-targets --all-features -- -D warnings`가 Linux 일반 실행 경로에서는 쓰지 않는 splitter 캐시 최적화 API를 dead-code로 보고하던 문제를, 해당 API와 보조 domain 계산 함수를 Windows target 및 테스트 빌드 전용으로 제한해 정리했다.
- 2026-06-17 추가 점검에서 Linux region 제목이 UI 언어가 한국어여도 `Region ...` 영어로 남던 문제를 Win32의 `영역 ...`/`영역 ... - 배치됨` 표시와 맞췄다.

남은 차이점:

- Wayland에서는 외부 창 제어 자체가 불가능하다. 동일 동작이 필요한 Linux 환경은 X11 세션이어야 한다.
- Linux에는 Win32의 owner window와 정확히 같은 개념이 없어, dock 중 `_NET_WM_STATE_ABOVE`를 사용한다. 이는 owner 관계보다 넓은 window-manager 상태이므로 WM 정책과 다른 top-level window와의 stacking에는 영향이 남을 수 있다.
- Linux X11 restore는 minimized/maximized display state와 dock 중 ABOVE 상태까지 보정했지만, Win32처럼 style/owner/per-owner z-order를 모두 복원하지는 못한다.
- Linux tab preset 불러오기의 자동 dock은 xterm 기준 실검증됐다. 다만 `_NET_WM_PID`와 `/proc` 기반 process tree scan으로 새 X11 top-level window를 찾으므로, 이 정보를 제공하지 않는 툴킷, launcher, sandbox 환경에서는 프로그램 실행은 성공해도 자동 dock이 실패할 수 있다.
- Linux 외부 창 focus/activation에서 active region을 따라가는 동작은 `_NET_ACTIVE_WINDOW` 또는 input focus를 제공하는 X11 WM 기준으로 보정했다. 다만 WM 정책과 stacking 영향을 받아 Win32 owner/activation 흐름과 완전히 같다고 보기는 어렵다.
- KDE/Wayland 위 Xwayland 자동화에서 `xdotool windowclose`는 GTK surface가 먼저 파괴되어 `GdkSurface unexpectedly destroyed`/`_gdk_surface_destroy_hierarchy` assertion이 재현된다. 이는 앱 내부 `Window > Close` 명령이나 창 장식 close 클릭이 아니라, 외부 도구가 X11 close protocol을 직접 보내는 검증 방식의 backend 한계로 분리한다.
